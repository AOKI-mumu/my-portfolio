把内容、文档、视觉和素材整理，拆成四个本地 AI Skills

我把四类重复任务拆成四个本地 skills：SEO JSON Writer 写网页 JSON 文案，Flaq Readme 写模型 README，Flaq Visual Prompts 写 cover/carousel 视觉 prompt，Asset Optimizer 处理素材命名和压缩。它们不是同一个项目里的四个步骤，而是四种不同工作，不能混在一个通用 prompt 里。

01. 项目背景

这个问题最先出现在网页 SEO 文案里。aitryon.art、heydream.im、ugcmaker.org 和 musicmaker.im 都有大量生成器、模型页或工具页；每个页面都要按固定 JSON schema 写标题、描述、示例、功能、使用场景、FAQ 和 CTA。

后来我发现 flaq.ai 的模型 README、cover/carousel 视觉 prompt 和日常素材整理也有类似问题，但它们不是 SEO JSON 的变体。README 要跟固定模板，视觉 prompt 要先判断图片是否好看、能不能复制，素材处理要先检查命名和冲突。放进同一个 prompt，只会互相污染。

02. 核心问题

问题不是 AI 会不会写，而是它有没有被放进对的规则里。SEO JSON Writer 不能乱改 key 和 section 顺序；Flaq Readme 不能套网页 SEO 的结构；Flaq Visual Prompts 不能为了统一风格牺牲单张图；Asset Optimizer 不能跳过文件预检。边界一模糊，后面就全是返工。

  • 四个 SEO 站点需要稳定 JSON 页面文案，但每个站点都有自己的 schema 和语气。
  • Flaq README 属于模型文档，不应该套用网页落地页的写法。
  • Cover 和 carousel 临时写 prompt 时，可能这张好看，下一张就跑偏。
  • 图片和视频素材数量多，人工命名检查、压缩和转换很容易漏掉冲突。

03. 系统策略

我的做法很简单：按任务拆，不做万能助手。SEO JSON Writer 管网页 JSON 文案，Flaq Readme 管 flaq.ai 模型 README，Flaq Visual Prompts 管 cover 和 carousel 的视觉 prompt，Asset Optimizer 管图片和视频素材。每个 skill 只回答一件事：什么时候用，先看什么，哪些地方不能乱动，最后怎么验收。

任务分流先判断是 SEO JSON、Flaq README、视觉 prompt，还是素材处理。
参考锁定SEO 跟参考 JSON，Flaq 跟固定 README 模板，视觉 prompt 跟审美 memory，素材处理跟目录范围。
Memory 检索复用历史页面摘要、已采纳 SEO 经验和视觉偏好。
脚本校验用导入、索引、预检和 audit 脚本减少手动检查。
人工审核我保留最终判断：事实、结构、SEO 意图和交付质量。

04. 工作流设计

SEO JSON Writer 是这套系统里最重要的 skill。它服务的是网页 SEO JSON 文案，主要用在 aitryon.art、heydream.im、ugcmaker.org 和 musicmaker.im。它不会自由发挥页面结构，而是先把参考 JSON 当成唯一结构来源，保留 key 名、嵌套、section 顺序、H2 模式和 CTA 字段。写作前会检索本地 memory，写完后再做 JSON 校验和 SEO 竞品 review，用来补关键词和搜索意图，但不复制竞品。

参考 JSON把参考文件作为唯一 schema 来源，不改 key 和 section 顺序。
Memory 检索查找相似 slug、模型、工具页和历史 SEO 经验。
竞品 Review补足搜索意图和关键词簇，但不复制竞品句子。
JSON 校验检查合法 JSON、schema 漂移、产品名和站点语气。

Flaq Readme 是另一条完全不同的线。它只服务 flaq.ai 的模型 README 写作，flaq.ai 是类似 WaveSpeed 的 API 聚合站，所以 README 更像模型/API 文档，而不是网页落地页。这个 skill 会读取固定模板，跟随模板的 H1、H2、段落节奏和 SEO 逻辑，同时根据模型参数约束文案。

Flaq Visual Prompts 和 flaq.ai 1.6 的关系最直接。1.6 增加了首页 carousel、模型入口和更多 cover 需求，视觉图开始变成高频交付物。这个 skill 的第一步不是统一风格，而是先让图过关：cover 要有主体和缩略图识别度，carousel 要有横向节奏、裁切安全和文字安全区。好图多了以后，再把有效经验写进 memory，慢慢收敛成更稳定的品牌风格。

Asset Optimizer 则更偏执行：它对应本地 rename-file 工作流，用来给图片和视频素材做命名预检、冲突检查、WebP 转换和压缩。

05. Skill 库

这四个 skills 是并列的，不是一个大流程里的四步。SEO JSON Writer 解决网页结构稳定，Flaq Readme 解决模型文档模板，Flaq Visual Prompts 解决 cover/carousel 的审美和复用，Asset Optimizer 解决文件处理里的低级错误。

SEO JSON Writer服务四个 AI 产品站点的 SEO JSON 页面，负责 schema 保真、memory 检索、竞品 review 和结构校验。
Flaq Readme服务 flaq.ai 模型 README，读取固定模板并根据模型参数写稳定文档。
Flaq Visual Prompts服务 flaq.ai cover 和 carousel。它是这里唯一直接跟 1.6 视觉工作有关的 skill。
Asset Optimizer基于本地 rename-file 工作流，处理图片和视频素材的命名预检、转换和压缩。

06. 前后对比

Dimension Before After
SEO 页面写作 临时 prompt 写页面，后面再人工改 JSON 结构 参考 schema + memory + SEO review + JSON 校验
模型文档 手动对照 flaq.ai 模板写模型 README 固定模板 + 模型参数约束 + 稳定 README 输出
Cover / carousel 视觉 临时写 prompt，这张可能好看，下一张容易跑偏 按 cover / carousel、裁切、安全区、主体和 memory 来写

任务边界 SEO、README、视觉 prompt、素材处理混在同一套要求里 按任务类型进入不同 skill，减少规则串台
人的角色 重复解释规则，并修正 AI 自由发挥后的偏差 集中审核事实、结构、审美判断和最终交付质量

07. 结果

SEO 生产更稳四个站点的 SEO JSON 页面可以按参考 schema 生产，不再每次重讲结构。
Flaq 文档稳定模型 README 能跟固定模板走，产出质量稳定，已经整合到项目 skill 中。
视觉生产可复制Cover 和 carousel 先看图能不能用，再把有效经验写回 memory。
素材处理更省心图片和视频素材先预检命名和冲突，再做转换压缩，减少手动漏项。

这套 skill 的价值不在于让 AI “什么都做”，而是让它少混淆任务。SEO 页面、模型 README、cover/carousel 视觉 prompt 和素材整理各有自己的输入、规则和验收方式，AI 只在这些边界里工作。

08. 下一步

  • 继续用 cover 和 carousel 的生成结果反推视觉 memory，先积累好图，再逐步统一 flaq.ai 的品牌视觉风格。
  • 把更多 GitHub 里的现成 skills 纳入日常流程，而不是每次从零写 prompt。
  • 用 humanizer 这类 skill 检查网页文案里的 AI 痕迹。
  • 用 design-taste-frontend 这类 skill 辅助检查页面视觉、交互和前端实现质量。
