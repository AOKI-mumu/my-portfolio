# Portfolio Content Rules

Use these rules when changing copy, case-study narrative, project data, or resume content.

## Positioning

- Present Lin Han hui as an AI / growth-focused Product Manager and Product Designer.
- Emphasize product planning, UX/UI, SEO content systems, testing, data review, and code collaboration.
- Avoid generic portfolio language when a specific shipped decision, constraint, or metric is available.

## Writing Style

- Lead with outcome, decision, and evidence.
- Keep paragraphs short.
- Use numbers when available.
- Explain constraints and tradeoffs.
- Be clear about ownership while keeping claims grounded.
- Avoid tool name-dropping unless the tool changed the outcome or workflow.

## Case Study Structure

Use this structure for aitryon and future comparable product cases:

1. Product context
2. Core problem
3. Product strategy
4. Experience redesign
5. SEO or growth system
6. Before / after comparison
7. Outcome
8. Next step

## Aitryon Story

- Frame as product experience and growth redesign, not only homepage redesign.
- Core narrative: from vertical AI try-on tool to broader AI image and video creation platform.
- Highlight generation entry, model/tool SEO architecture, JSON-based content skill, and AI Studio next step.
- Add concrete design decisions and visual evidence before treating the case as portfolio-ready.

## Metrics

- Keep current metrics consistent across homepage, case, and resume.
- Add data window and source note when possible.
- If public trend data is used, prefer source links or phrase it as market observation.

## Bilingual Rules

- All visible translatable copy should use `data-i18n`.
- Add both `translations.en` and `translations.zh` keys together.
- Brand/signature text may remain English-only when intentional, such as `Lin Han hui` and `Say hi! Let's talk`.
