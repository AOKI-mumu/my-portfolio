# AI Skill System for Repeated Production Work

## Working Title

From repeated AI tasks to four reusable local skills

## One-Line Summary

I turned repeated SEO writing, model documentation, cover/carousel prompting, asset cleanup, and product memory tasks into a local AI skill system with separate rules, searchable memory, validation scripts, and review loops.

## 01. Project Context

While working on AI SaaS products and this portfolio, I noticed that many tasks were not truly one-off. Model landing pages had to be updated whenever new AI models appeared. Tool pages needed consistent sections such as examples, core features, use cases, manuals, related tools, and FAQs. Model readmes needed to follow strict template logic. Cover and carousel prompts needed taste checks instead of one-off image ideas. Website assets still needed cleanup without breaking references. Portfolio decisions also needed to survive across multiple AI collaboration sessions.

At first, these tasks looked like separate writing or maintenance jobs. But the deeper pattern was the same: each task needed a clear reference, reusable judgment, guardrails, validation, and a way to carry learning into the next task.

## 02. Core Problem

The problem was not simply speed. AI could generate copy quickly, but fast output was not enough if the structure drifted, product facts became loose, SEO sections changed randomly, or previous decisions had to be re-explained every time.

I split the problem into four layers:

- Repeated tasks were scattered across prompts, memory, local notes, and manual habits.
- Different page types needed strict structure, but AI tended to improvise when the reference was not enforced.
- SEO optimization needed competitor awareness, but not at the cost of copying competitors or breaking the site schema.
- Portfolio and product decisions needed a persistent memory layer, otherwise each session started with too much rediscovery.

The goal became clearer: build a lightweight working system where AI could follow my product judgment instead of only responding to one prompt at a time.

## 03. System Strategy

My strategy was to treat skills as small product systems. Each skill has a defined trigger, scope, workflow, guardrails, reference files, scripts, and output requirements. Instead of asking AI to "write better copy" or "clean assets", the system tells it how to think, what to inspect first, what must be preserved, and how to validate the result.

The system is built around five layers:

- Skill rules: task-specific instructions and boundaries.
- Reference patterns: templates, page schemas, and accepted writing structures.
- Local memory: searchable summaries of existing pages and accepted SEO learnings.
- Scripts: repeatable import, indexing, audit, and validation helpers.
- Human review: final judgment on positioning, factual accuracy, and conversion quality.

## 04. Workflow Design

The clearest example is the SEO JSON Writer skill. It does not just draft SEO copy. It first treats the reference JSON as the source of truth, preserving key names, section order, H2 formulas, CTA fields, and nesting. Then it searches local memory for similar products, model families, or page patterns. After drafting, it validates the JSON structure and runs a competitor review to identify keyword and content gaps without copying competitors.

This changes the work from "generate a page" to "operate a content production workflow":

- Reference matching keeps page structure stable.
- Memory search reuses historical judgment without copying old pages.
- Competitor review improves search intent coverage.
- Schema validation catches structural drift.
- Accepted SEO learnings can be recorded back into memory.

The asset optimizer skill follows a similar principle. It does not directly compress or rename everything. It starts with an audit, reports conflicts, avoids hidden/system/build files, and only applies changes after the scope is clear. This made the workflow safer because asset cleanup can easily damage a website if file names or references are changed casually.

## 05. Skill Library

The current local skill library covers four recurring production areas:

- SEO JSON Writer: creates and updates structured SEO page JSON while preserving schema, local style, keyword logic, and competitor review discipline.
- Flaq Readme: writes model readmes against fixed reference templates, keeping model documentation consistent without copying template sentences.
- Flaq Visual Prompts: creates cover and carousel prompt directions that are beautiful, repeatable, and product-appropriate before narrowing into a more unified brand style.
- Asset Optimizer: audits and optimizes media assets with scope control, conflict detection, and safe apply behavior.

Together, they form a practical operating layer for AI product work: content creation, documentation, visual direction, and asset maintenance each get their own rules instead of being handled by one generic prompt.

## 07. Outcome

The main outcome is a more stable collaboration loop. AI assistance became less like a blank chat window and more like a set of productized workflows that can preserve structure, reuse context, and expose risks before changes are applied.

This system helped me express a broader product design capability: I can not only use AI tools, but also design the process around them. For AI SaaS work, that means turning fast-changing models, SEO pages, content updates, and delivery constraints into a repeatable operating system.

The value is not only efficiency. It is consistency, reviewability, and the ability to make future work better by writing useful decisions back into memory.

## 08. Next Step

The next step is to extend this system from content and assets into broader product design workflows:

- A portfolio case-study writing skill that keeps narrative, evidence, bilingual copy, and image requirements aligned.
- A design review skill that checks spacing, typography, visual hierarchy, and page consistency against local design rules.
- A bilingual content sync workflow that keeps English and Chinese copy updated together.
- A stronger visual asset workflow for process diagrams, evidence screenshots, and case-study covers.
